# ALC-06A 四份题库能力矩阵

版本：1.0  
盘点日期：2026-08-13  
适用范围：`@ide-agent/core` 本地 LD/FBD 单节点渐进式建议

## 1. 盘点目的

本矩阵逐项对照四份场景题库与当前项目实现，回答三个问题：

1. 题目中的通用业务关系是否已经由当前规则和代码支持。
2. 已有能力应直接复用、适当增强，还是确实存在新的通用缺口。
3. 哪些内容依赖完整状态机、安全设计或专用设备模型，不应纳入当前本地渐进式补全。

本阶段只做能力盘点，不修改 `businessRules.json`、核心代码或测试。

## 2. 判定口径

状态只评价当前“选中节点，每次补一个节点”的本地建议能力，不评价生成 skill 能否一次生成完整梯形图。

| 状态 | 含义 |
|---|---|
| `supported` | 题目中适合单节点补全的核心关系已有规则、实现和基本回归覆盖；仍不代表可以一键生成整套程序。 |
| `partial` | 已有相同或相近机制，能覆盖一部分核心关系，但仍缺少通用识别、同组判断、绑定、去重或业务关系建模。后续应优先增强现有机制。 |
| `unsupported` | 业务关系适合本地渐进式补全，但当前没有可复用实现。新增机制前必须证明现有结构无法表达。 |
| `out_of_scope` | 核心目标依赖多步骤状态机、全局调度、安全设计、专用设备模型或一次生成多节点，不纳入当前规则引擎。已有基础元件建议仍可继续工作。 |

当一个题目包含多种能力时，以其核心业务目标确定状态，并在“现有覆盖与缺口”中分别说明已支持部分和未支持部分。

## 3. 当前能力基线

以下编号用于矩阵中的“现有覆盖”列。它们都是当前项目已有机制，后续不得为相同语义另建平行规则。

| 能力 | 当前规则或实现 |
|---|---|
| 定时与反馈超时 | `T01`～`T07`、`LS06`～`LS15`；TON/TOF/TP、最小运行/停机文字和命令反馈超时 |
| 计数与沿 | `C01`～`C03`、`E01/E02`、`NI13`；CTU/CTD/CTUD 和单次计数沿 |
| 锁存与启停释放 | `L01/L02`、`AL01`～`AL03`；SR/RS、自保持、停止常闭释放、置位动作复位 |
| 设备动作许可 | `DL01`～`DL05`；就绪、故障、许可、阻断、物料存在条件及同设备/动作分组 |
| 故障响应与复位 | `FR01/FR02`、`FRS01`；报警输出、故障置位锁存和独立复位路径 |
| 触点极性和业务文案 | `P01/P02`、`NI01`～`NI13`；许可常开、故障/阻断常闭及可靠证据下的业务 title/text |
| PID 与过程回路 | `P01`～`P03`、`LS02/LS05/LS10`；PV/SP/MV 类型和同回路完整性 |
| 数值处理 | `N01`～`N08`；LIMIT/MIN/MAX、比较、RAMP、HYSTERESIS、MUX |
| 模式选择 | `SEL01`、`LS13`；自动/手动等二选一选择条件完整时推荐 SEL |
| 字符串处理 | `STR01`～`STR06`；LEFT/RIGHT/MID/CONCAT/FIND/LEN |
| 运动控制 | `MC02`～`MC10`、`LS04/LS09`、同轴上下文；MC_Power/Reset/Home/Move/Stop/Halt |
| 已有节点和同组去重 | 各 completion 分析器、同设备/动作判断、库端口校验和拓扑合法性检查 |
| 明确不自动生成 | `V2-state-machine-ownership`、`V2-safety-function`、`V2-motor-valve-cylinder-template`、`V2-pid-engineering` |

主要回归入口：

- `local-business-suggestion-fixture.json`：通用库规则、极性、业务文案和去重。
- `loop-signature-business-suggestion-fixture.json`：PID/TON 签名、分组、类型和已有块去重。
- `device-loop-completion-fixture.json`：设备许可、故障联锁、输送段和工位动作。
- `fault-response-completion-fixture.json`：故障/超时后的报警与锁存。
- `fault-reset-completion-fixture.json`：故障锁存的独立复位。
- `action-lifecycle-completion-fixture.json`：自保持、停止释放和置位动作复位。
- `motion-axis-context-fixture.json`：同轴运动命令上下文。

## 8. 盘点结论

### 8.1 不能重复建设的现有能力

四份题库中反复出现的以下内容已经有通用机制，后续只应增强或补回归：

- TON/TOF/TP、反馈超时和最小运行/停机语义。
- CTU/CTD/CTUD、上升沿和批次计数基础能力。
- 启停自保持、停止常闭释放、故障锁存和独立复位。
- 动作前就绪/许可/无故障/无阻断条件。
- PID、RAMP、LIMIT、HYSTERESIS、SEL 和比较函数。
- MC_Power/Home/MoveAbsolute/MoveRelative/MoveVelocity/Stop/Halt/Reset。
- LEFT/RIGHT/MID/CONCAT/FIND/LEN。

这些题库表达即使设备名称不同，也必须复用当前同一条业务链，不能再创建“水泵 TON”“风机 TON”“输送机 TON”等平行规则。

### 8.2 值得进入 ALC-06B 评审的通用缺口

以下是矩阵中多次出现、但当前仅部分支持的通用关系：

1. **同类设备选择与轮换**：多泵、多风机、多压缩机的首选设备、备用投入、故障跳过和运行时间均衡。
2. **共享资源请求仲裁**：双输送线合流、双工位分配等多个请求竞争同一资源时的许可和优先级。
3. **计数完成后的动作闭环**：计数器完成输出与批次完成、停机或复位之间的同组关系。
4. **相反动作互斥证据**：开/关、伸/缩、正/反、加热/冷却等同设备相反动作的阻断条件和去重。
5. **运动动作组合证据**：已有 MC 规则基础上，增强回零、移动、点动、限位、到位和超时的同轴/同动作关联，但不接管完整步骤顺序。

这些项目首先评估能否增强现有 `variablePatterns`、端口角色、`DL01`～`DL05`、`loopSignatures`、`actionLifecycleRules` 和已有分组逻辑。只有现有结构无法表达时，才提出新机制设计。

### 8.3 不进入 ALC-06B 的内容

- 多步骤生产顺序、循环阶段、跳步和任务恢复。
- 一次生成整条设备模板或跨多个区段的程序。
- 泵组/工位的全局调度算法和运行时状态持久化，除非后续具备明确设备模型。
- 急停、消防、双手启动、光幕、防夹、气闸、锅炉/燃烧/泄压等安全功能设计。
- PID 参数整定、单位量程、采样周期、双传感器表决和同步控制算法。

这些内容可以继续使用已有基础元件建议，但不能据此宣称完整业务场景已经由本地规则支持。

## 9. ALC-06B 建议顺序

1. 先处理“计数完成后的动作闭环”，它与现有计数端口角色、AL/FR 关系最近，改动相对可控。
2. 再处理“相反动作互斥证据”，优先增强 DL 的同设备/动作分组和阻断候选。
3. 再评估“运动动作组合证据”，限定在同轴和单节点建议内。
4. “同类设备选择与轮换”“共享资源仲裁”先做输入模型评估；若缺少可靠运行状态和所有权，不应仅靠变量名实现。

ALC-06C 只为已经真实实现的能力增加正反例，不为本矩阵中的 `out_of_scope` 场景伪造通过测试。
