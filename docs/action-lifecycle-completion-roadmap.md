# 通用动作生命周期补全路线

版本：1.0  
状态：分阶段实施  
适用模块：`@ide-agent/core` 本地 LD/FBD suggestions

## 1. 目标

从泵、电机、输送段、阀门、气缸、工位动作和运动控制题库中提炼跨设备通用的局部规律，逐步补齐一条动作链中缺失的业务节点：

```text
动作请求 -> 许可/就绪/阻断联锁 -> 动作命令
         -> 运行/到位反馈 -> 超时监控
         -> 报警或故障锁存 -> 人工复位
```

本路线保持当前“选中一个节点，每次建议添加一个节点”的交互方式，不实现一次性生成完整设备模板。

## 2. 范围边界

### 2.1 纳入范围

- 变量名、类型、标签、备注、注释和功能块端口能够提供可靠证据的通用角色判断。
- 同一设备或动作组内的命令、许可、就绪、阻断、运行反馈、到位反馈、超时参数、故障和复位关系。
- 只返回存在于 `st-library-info-data.json` 的函数或功能块。
- 复用当前拓扑计算、`startNodes/endNodes`、业务标题和说明文案。

### 2.2 暂不纳入

- 一次性生成跨多个节点或多个区段的完整模板。
- 没有输入模型时推断 SFC、状态机、设备 FB 或程序所有权。
- 自动设计安全回路、急停回路、SIL/PL 功能或风险控制逻辑。
- 需要单位、量程、采样周期、PID 调参或工程验证的数据闭环。

## 3. 实施原则

1. 先确认当前链路已经存在什么，再推荐缺少的环节。
2. 当前区段和选中节点优先，其他区段只作为辅助证据。
3. 有明确设备/动作分组时才绑定真实变量；证据不足时退回结构建议。
4. 已存在的功能块、端口绑定或同路径变量不得重复推荐。
5. 运行反馈/到位反馈是动作结果，不自动作为命令启动前置条件。
6. 不同设备或同工位不同动作不得因为公共前缀相似而混用。
7. 业务文案只在证据达到门槛时启用，否则保留原有拓扑描述。

## 4. 任务状态

状态值：

- `pending`：尚未开始。
- `in_progress`：正在实现和测试。
- `completed`：代码、规则、正反例测试和文档均已完成。
- `blocked`：缺少输入模型或外部能力，暂不实现，仅记录降级行为。

| ID | 任务 | 状态 | 验收标准 |
|---|---|---|---|
| ALC-01 | 命令 + 运行/到位反馈 + 超时时间缺少 TON | `completed` | 同设备/动作组同时具备 `commandSignal`、`runFeedback` 或 `completionSignal`、`presetDuration`，且没有同组 TON 时，推荐真实库中的 TON；缺任一角色、已有 TON、跨组变量时不推荐。 |
| ALC-02 | 动作命令缺许可、就绪或故障联锁 | `completed` | 仅在命令锚点和候选条件属于同一设备/动作组且路径未使用时，分别推荐常开许可/就绪或常闭故障/阻断；反馈不得变成启动前置。 |
| ALC-03 | 超时/故障条件缺报警或故障锁存 | `completed` | 已有超时或故障证据且当前路径缺少对应报警/锁存输出时，推荐一个合法的报警输出或置位线圈；安全场景降级。 |
| ALC-04 | 故障锁存缺复位路径 | `completed` | 已有独立复位条件且另一独立区段存在同组故障锁存置位线圈、但尚无对应复位线圈时，推荐绑定同一锁存变量的复位线圈；已有复位、跨组或无法确认归属时不推荐。 |
| ALC-05 | 启停缺自保持或释放逻辑 | `completed` | 能确认启动请求、停止请求和同一动作输出的关系时，补充自保持或释放建议；只有单个按钮或未知线圈时退回拓扑建议。 |
| ALC-06A | 四份题库能力盘点与现有规则映射 | `completed` | 逐项判断题库场景为已支持、部分支持、未支持或不纳入，并记录对应的现有规则、实现入口和测试；本阶段只形成能力矩阵，不修改代码，也不把未实现能力写成已支持。 |
| ALC-06B-1 | 计数完成后的动作闭环 | `completed` | 复用计数端口角色、设备/动作分组和现有生命周期机制；真实 CTU/CTD/CTUD 的唯一已绑定 BOOL 完成端口存在同组批次完成变量时补普通或置位线圈，已有输出、跨组、未绑定端口、缺少真实计数器或安全场景不推荐。 |
| ALC-06B-2 | 相反动作互锁证据 | `pending` | 增强现有动作角色和 `DL04` 阻断逻辑，通用覆盖开/关、伸/缩、正/反、加热/冷却等同设备相反动作；不得为每类设备复制规则，也不得把反馈误作命令互锁。 |
| ALC-06B-3 | 运动动作组合证据 | `pending` | 增强现有 MC 规则、端口角色和同轴上下文，识别回零、移动、点动、限位、到位和超时的同轴关系，以及 Enable 型与 Execute 型命令差异；不接管完整运动步骤。 |
| ALC-06B-4 | 同类设备选择与轮换输入模型评估 | `pending` | 评估泵、风机、压缩机等同类设备的设备集合、可用状态、首选状态、累计运行量和故障跳过证据能否可靠获得；本任务不直接启用轮换建议。 |
| ALC-06B-5 | 共享资源请求仲裁输入模型评估 | `pending` | 评估多请求方、共享资源、占用状态、优先级和释放条件能否可靠表达；本任务不根据变量名直接生成仲裁逻辑。 |
| ALC-06C | 已实现能力的正反例回归收口 | `pending` | 为 ALC-01 至 ALC-06B 中已真实实现的能力补齐题库来源、正例、已有逻辑去重、跨设备/动作、缺证据和安全排除测试；测试不得代替功能实现。 |

## 5. ALC-06 拆分方案

ALC-06 不是“把四份题库全部改写成测试”。它先对照当前项目判断已经支持什么，再补通用缺口，最后才对已经存在的能力补齐回归测试。

盘点来源：

- `plc-ladder-json-prompts.txt`
- `complex_parallel_ladder_requirements_1_20.txt`
- `infer_parallel_ladder_requirements_1_20.txt`
- `infer_special_library_requirements_1_12.txt`

### 5.1 总体约束

1. 以当前 `businessRules.json`、`LocalGraphSuggestionCore.ts` 和既有 fixture 为能力基线，不能只看题库文本判断是否缺规则。
2. 题库场景与现有规则语义相同或相近时，不新增一套平行规则；应复用现有规则，按需补充词汇、角色证据、触发条件、绑定、文案或去重边界。
3. 已完整支持的场景只登记映射并补缺失的回归测试，不重复实现。
4. 部分支持的场景只补实际缺口。例如已经识别“故障”，但尚不能确认同一设备/动作时，应增强分组证据，而不是再写一条新的故障推荐链。
5. 只有现有规则结构无法表达一种独立业务关系时才允许新增规则。新增前必须记录不能复用哪个现有机制以及原因。
6. 不为单个题目、固定 POU 名、节点 ID 或特定变量名编写专用规则；题库案例必须先抽象成跨设备可复用的业务关系。
7. 复杂状态机、安全逻辑和专用设备策略可以标记为不纳入或后续阶段，不追求题库数量上的全覆盖。

### 5.2 ALC-06A：能力盘点与映射

本阶段不修改规则和核心代码。输出一份能力矩阵，每个题库场景至少记录：

| 字段 | 含义 |
|---|---|
| 来源 | 题库文件和题目编号 |
| 通用业务关系 | 去掉具体设备名后的业务意图，例如“动作命令缺故障联锁” |
| 当前状态 | `supported`、`partial`、`unsupported` 或 `out_of_scope` |
| 现有覆盖证据 | 对应的 term、角色规则、签名、补全规则、实现函数和 fixture |
| 实际缺口 | 当前缺少的识别、分组、绑定、排序、文案、去重或拓扑能力 |
| 处理决定 | 仅补测试、增强现有机制、确需新增机制、延期或明确排除 |
| 正反例要求 | 后续验证该决定所需的最小正例和关键反例 |

状态判断标准：

- `supported`：当前代码已经能生成正确建议，并具备必要的去重和边界控制。
- `partial`：主要机制已经存在，但在部分通用表达、变量角色、同组判断、绑定或反例上存在明确缺口。
- `unsupported`：当前没有能够表达该业务关系的实现，且它属于本地渐进式补全的合理范围。
- `out_of_scope`：依赖完整状态机、工艺时序、安全设计、专用设备模型或其他当前不具备的输入。

ALC-06A 的完成不代表新增业务能力，只代表项目已经明确题库覆盖现状和后续取舍。

### 5.3 ALC-06B：通用缺口补齐

只从能力矩阵的 `partial` 和经过评审的 `unsupported` 项中选择实现对象，并按以下顺序处理：

1. 补充现有 `termPatterns` 或 `termImplications`，解决同一语义的常见表达遗漏。
2. 增强现有变量角色、功能块端口角色和设备/动作归属证据。
3. 增强现有 `loopSignatures`、`deviceLoopRules`、`faultResponseRules`、`faultResetRules`、`actionLifecycleRules` 或 `libraryRules` 的条件、绑定与去重。
4. 现有数据结构确实无法表达时，再设计新的通用字段或规则类型，并说明与已有机制的职责边界。

每个实现批次必须同时做到：

- 指明复用或增强的现有规则 ID/实现入口。
- 不改变已完成 ALC-01 至 ALC-05 的正确行为。
- 候选功能块和端口继续严格取自 `st-library-info-data.json`。
- 至少包含一个通用正例和一个能防止误配的关键反例。

以下内容不在本阶段强行补齐：

- 需要一次生成多个节点、多个区段或完整设备程序的题目。
- 需要理解完整步骤顺序和状态转换的复杂状态机。
- 安全回路、急停、SIL/PL 或风险控制逻辑的自动设计。
- 只能服务某个厂商、项目或固定命名的专用策略。

#### 5.3.1 ALC-06B-1：计数完成后的动作闭环

目标是补齐“计数已经达到目标，接下来应该结束、标记或复位什么”的局部业务关系，而不是重新实现 CTU/CTD/CTUD 推荐。

优先复用：

- `C01`～`C03` 的计数器选择和现有 `BPR03-counters` 端口角色。
- 现有设备/动作分组、功能块端口绑定和已有节点去重。
- `actionLifecycleRules`、故障/状态输出和线圈生成能力。

拟支持的局部建议：

- 真实计数器完成输出或同组完成信号存在，缺少同组批次完成状态时，推荐已有 BOOL 完成变量的线圈或置位线圈。
- 同组完成条件与运行输出关系明确时，推荐停止/释放条件，但不能凭“计数”两个字猜测停机变量。
- 独立清零或下一批复位条件存在时，复用已有复位/释放机制，避免重复生成复位路径。

ALC-06B-1 本次验收只纳入第一项，即“真实计数器完成端口 -> 同组批次完成输出”。后两项仍要求独立、明确的运行/停止/复位锚点；当前不会仅凭计数器自动推断停机或下一批复位，后续输入条件成熟时再作为单独增强任务评审。

不纳入：

- 自动创建完整“计数→停机→确认→清零→下一批”多区段模板。
- 没有真实计数器、完成端口绑定或同组完成变量时推断整个批次流程。

验收至少覆盖：真实 CTU 完成正例、已有完成输出去重、跨设备/批次排除、缺少计数器反例和安全语义降级。

#### 5.3.2 ALC-06B-2：相反动作互锁证据

目标是增强已有 `DL04-action-inhibit-interlock`，让系统识别同一设备上的相反动作，避免开/关、伸/缩、正/反等输出同时成立。

优先复用：

- `deviceLoopRules` 的命令锚点、候选变量绑定和同设备/动作归属判断。
- `inhibitSignal`、`commandSignal`、`actionOutput` 等现有变量角色。
- `contactPolarityRules` 的常闭阻断极性，不新增另一套触点极性逻辑。

拟增强的通用动作对：

- `open` ↔ `close`
- `extend/push` ↔ `retract`
- `forward` ↔ `reverse`
- `heat` ↔ `cool`
- 其他只有在配置中明确声明的互斥动作对

关键边界：

- 必须属于同一设备，并能确认是两个相反命令或动作输出。
- 运行反馈、到位反馈不能直接当作相反命令。
- 同设备但不同、不互斥的动作不得阻断，例如夹紧与推料不能仅凭公共工位名前缀互锁。
- 安全联锁继续走既有安全边界，本阶段不生成安全回路。

验收至少覆盖开/关和正/反正例、已有互锁去重、反馈不得误用、跨设备排除、同设备非相反动作排除。

#### 5.3.3 ALC-06B-3：运动动作组合证据

目标是在现有 `MC02`～`MC10` 和同轴上下文上补充动作关系，不重新定义 MC 功能块推荐。

优先复用：

- `BPR05-motion`、`LS04/LS09` 和已有 MC `libraryRules`。
- `analyzeMotionAxisContext` 的 `AXIS_REF` 同轴判断。
- 库文件中的真实端口方向和类型，特别是 `VAR_IN_OUT` Axis 端口。

拟增强内容：

- 区分 `MC_Power.Enable` 的保持型使能语义与运动命令 `Execute` 的触发周期语义。
- 在同一轴内利用 Home、Done、Busy、Error、限位、到位和超时证据改善建议与业务说明。
- 对同轴相反或冲突命令提供互锁候选证据，但不根据静态图假定运行时命令正在执行。

不纳入：

- 自动生成“上电→回零→定位→停止”的完整步骤链。
- 根据静态图推断轴实时状态、命令调度器或厂商运动状态机。
- 修改当前 MC_Stop/MC_Halt 已验证的区分和端口生成格式。

验收至少覆盖同轴组合正例、不同轴排除、Axis 未绑定降级、已有命令去重和 MC_Power/Execute 语义不混淆。

#### 5.3.4 ALC-06B-4：同类设备选择与轮换输入模型评估

本阶段只评估，不实现轮换推荐。需要先确认输入数据能否可靠表达：

- 哪些设备属于同一个可轮换集合。
- 每台设备的可用、故障、检修和手动锁定状态。
- 当前首选设备、运行小时或启动次数。
- 投入/退出条件、最小运行/停机约束和故障跳过策略。

验收产物是字段来源、可信度、缺失时降级方式和正反例草案。若只能依靠 `Pump1/Pump2` 等名称猜测，则结论应为 `blocked`，不能创建活动规则。评估通过后另立实现任务，不直接把 B-4 标为业务能力完成。

#### 5.3.5 ALC-06B-5：共享资源请求仲裁输入模型评估

本阶段只评估，不实现仲裁建议。需要先确认输入数据能否可靠表达：

- 多个请求方和唯一共享资源的归属关系。
- 资源当前占用方、空闲/释放状态和不可抢占条件。
- 固定优先级、交替优先或先到先服务等仲裁策略。
- 请求取消、超时和异常释放行为。

验收产物同样是输入模型和边界说明。没有明确资源 ID、请求方 ID、占用状态和策略时，不得只靠变量名生成优先级或互斥逻辑。评估通过后另立实现任务。

#### 5.3.6 实施顺序

```text
ALC-06B-1 计数完成闭环
  -> ALC-06B-2 相反动作互锁
  -> ALC-06B-3 运动动作组合
  -> ALC-06B-4 同类设备轮换模型评估
  -> ALC-06B-5 共享资源仲裁模型评估
```

B-1 至 B-3 每完成一项，都必须同步更新规则字段文档和对应 fixture。B-4、B-5 在评估结论明确前不得进入规则文件。

### 5.4 ALC-06C：回归测试收口

本阶段只测试已经真实存在的能力，包括 ALC-01 至 ALC-05、ALC-06B 的增强项以及题库中已由旧规则覆盖的场景。

每类能力至少覆盖：

- 正常命中的正例。
- 已有目标节点、功能块或端口绑定时不重复推荐。
- 同 POU 中不同设备、同设备不同动作不得串线。
- 缺少必要角色、类型或归属证据时不强行推荐。
- 安全语义按既有边界降级。
- `startNodes/endNodes` 等拓扑边界保持合法。

未实现的题库场景只能保留在能力矩阵中，不能用跳过测试、空断言或伪造期望结果宣称已经覆盖。

### 5.5 ALC-06 整体验收

ALC-06C 完成后，必须能够从任一纳入的题库场景追溯到：

```text
题库题目
  -> 通用业务关系
  -> 复用/增强的现有规则或经批准的新机制
  -> 正反例 fixture
  -> 测试断言
```

不要求四份题库的所有题目都进入自动补全；要求所有题目都有明确、可解释且不重复建设的处理结论。

## 6. 阶段一详细设计：ALC-01

### 6.1 触发条件

满足以下条件才进入通用反馈超时判断：

- 同一设备或动作组具备 `commandSignal`。
- 同组具备 `runFeedback` 或 `completionSignal`。
- 同组具备 `presetDuration`，类型必须为 `TIME`。
- 当前组没有已存在的 TON 实例或同路径 TON 建议。
- 当前上下文不是安全逻辑，且存在合法的功能块插入位置。

### 6.2 推荐结果

推荐库中的 `TON`，端口必须从 `st-library-info-data.json` 读取：

- `IN`：BOOL 命令或动作监控条件。
- `PT`：TIME 超时时间。
- `Q`：BOOL 超时结果。

具体端口变量绑定仍由用户在渐进式建议中确认，不凭空创建业务变量名。

### 6.3 不应推荐的情况

- 只有命令，没有反馈或到位信号。
- 只有反馈，没有命令锚点。
- 超时时间属于另一台设备或另一个动作。
- 同一动作组已经存在 TON。
- 当前逻辑属于安全、急停或风险控制语义。

## 7. 测试要求

每个阶段必须至少包含：

- 一个满足条件的正例。
- 一个缺少必要条件的不推荐反例。
- 一个已有目标功能块的不重复反例。
- 一个跨设备或跨动作不串线反例。
- 一个安全语义降级反例（适用时）。

阶段完成后，必须更新本表状态和对应测试结果；未完成阶段不得在规则文件中伪装成 `active` 能力。
