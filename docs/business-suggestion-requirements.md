# LD/FBD 业务语义补全需求说明

## 目标

在现有本地 LD/FBD 拓扑建议能力之上，新增一层业务语义排序能力，让返回的 suggestions 不只满足图结构合法性，还能更贴近真实 PLC 工程习惯。

当前能力主要回答：

- 当前位置能不能前串联、后串联、并联、替换；
- 新增节点的 `startNodes` / `endNodes` 应该如何连接；
- 新增节点是触点、线圈还是功能块。

业务语义补全希望进一步回答：

- 当前业务场景下，哪类建议更常见；
- 当前区段更像启动、停止、报警、复位、延时、运动控制还是互锁逻辑；
- 同样合法的多条建议中，哪一条应该排在前面。

## 基本原则

1. 拓扑合法性优先

   先使用现有本地规则生成合法 suggestions，保证 IEC-61131 图结构、`startNodes`、`endNodes`、`position`、`serialOrParallel`、`addNode` 等字段正确。

2. 业务规则以排序为主

   业务规则主要用于对已有 suggestions 加分、降分和排序，不默认删除拓扑上合法的建议。

   只有当某条建议明显违反 IEC-61131 结构或业务硬约束时，才允许过滤。

3. 新增节点默认不强行命名

   新增节点仍然保持当前约定：

   ```json
   "value": "???"
   ```

   业务语义用于判断“更应该推荐什么类型、什么位置、什么优先级”，不负责凭空生成变量名。

4. 上下文不足时降级

   如果当前区段只有未命名节点，且没有区段名称、备注、变量名、端口名等业务信息，则只返回拓扑建议，不强行猜测业务。

## 上下文分层策略

业务分析按以下优先级获取上下文。

### 1. 当前区段优先

当前 segment 的信息权重最高，包括：

- 当前选中节点；
- 当前节点前后相邻节点；
- 当前区段内所有变量名；
- 当前区段内功能块类型；
- 当前区段的 `label`；
- 当前区段的 `note`；
- 当前区段上下游结构；
- 当前区段是否已有输出节点。

例如：

- 当前区段名称包含“报警复位”，则复位线圈、故障相关触点优先级提高；
- 当前区段包含 `TON`，则触发条件、定时完成输出相关建议优先级提高；
- 当前选中节点位于输出前，则优先推荐输出相关或条件补充建议。

### 2. 当前 POU 为主

当当前区段信息不足时，可以参考同一 POU 内的其他区段和变量表。

可参考内容：

- 同一 POU 的变量列表；
- 同一 POU 其他区段中变量共现关系；
- 同一设备前缀下的相关变量；
- 同一功能块实例相关的输入输出变量。

例如：

```text
Motor1_Start
Motor1_Run
Motor1_Fault
Motor1_Reset
```

如果当前区段已经出现 `Motor1_Start`，则同 POU 中的 `Motor1_Fault`、`Motor1_Run` 可以作为业务判断依据。

注意：这些变量只用于排序和提示，不直接替换新增节点的 `???`。

### 3. 项目级按需召回

只有当前区段和当前 POU 信息不足时，才按需参考项目级信息。

项目级信息可以包括：

- 项目变量库；
- 历史同类 POU；
- 常见模板；
- 用户配置的业务规则；
- 行业或设备类型配置。

不建议每次 suggestion 都全量扫描项目，避免性能下降。

## 可利用的业务语义

### 变量名关键词

从变量名中识别业务角色。

常见关键词示例：

| 关键词 | 可能含义 | 建议倾向 |
| --- | --- | --- |
| `Start` / `Run` | 启动、运行 | 常开触点、置位线圈、自保持相关建议 |
| `Stop` | 停止 | 常闭触点、复位线圈 |
| `Enable` | 使能 | 常开触点、功能块 EN 前条件 |
| `Ready` | 就绪 | 常开触点、运行允许条件 |
| `Fault` / `Error` | 故障、错误 | 故障互锁、复位、报警相关建议 |
| `Alarm` | 报警 | 置位线圈、复位线圈、报警保持 |
| `Reset` | 复位 | 复位线圈、复位功能块前置条件 |
| `Busy` | 忙 | 运行状态判断、互锁 |
| `Done` | 完成 | 后续动作触发条件 |

关键词不是只看选中节点本身，也可以看：

- 选中节点变量名；
- 直接前后节点变量名；
- 当前功能块端口变量名；
- 当前区段内变量名；
- 当前 POU 变量表。

### 同一设备信号关联

通过变量命名前缀识别同一设备或同一对象。

例如：

```text
Pump1_Start
Pump1_Run
Pump1_Fault
Pump1_Reset
```

如果当前区段出现 `Pump1_Start`，则与 `Pump1_Run`、`Pump1_Fault`、`Pump1_Reset` 相关的建议可以获得更高优先级。

当前阶段不直接生成这些变量名，新增节点仍然是 `???`。

### 功能块类型偏好

不同功能块有不同的常见补全方向。

| 功能块 | 业务倾向 |
| --- | --- |
| `MC_Reset` | 前面优先补 Enable / Fault / Ready 相关条件触点 |
| `TON` / `TOF` / `TP` | 前面补触发条件，后面使用 Q/ET 等输出 |
| `CTU` / `CTD` | 前面补计数条件，后面使用 Q/CV 等输出 |
| `SR` / `RS` | 补置位条件、复位条件、输出状态使用 |
| 运动控制类 FB | 优先考虑 Enable、Execute、Busy、Done、Error、Ready、Fault |

### 区段名称和备注

区段的 `label` 和 `note` 可以直接影响业务排序。

示例：

- “启动控制”：提高常开触点、置位线圈、自保持建议；
- “停止控制”：提高常闭触点、复位线圈建议；
- “报警复位”：提高报警、故障、复位相关建议；
- “低压延时”：提高 `TON`、压力相关条件、延时输出建议；
- “互锁”：提高常闭触点、故障/运行状态条件建议。

### 上下游结构

根据当前图结构判断业务位置。

示例：

- 当前区段无输出节点：输出线圈建议优先级提高；
- 当前节点在功能块 EN 前：条件触点建议优先级提高；
- 当前节点在并联分支内部：避免把输出节点错误加在分支内部；
- 当前节点后面已有输出：降低继续添加输出线圈的优先级；
- 当前节点附近已有故障/停止条件：互锁类建议优先级提高。

## 业务规则表建议

可以新增一个配置化规则表，例如 `businessRules.json` 或 TypeScript 常量。

示例：

```json
{
  "keywords": {
    "Fault": {
      "boost": ["negatedContact", "resetCoil"],
      "scenes": ["interlock", "alarm", "reset"]
    },
    "Alarm": {
      "boost": ["setCoil", "resetCoil"],
      "scenes": ["alarm"]
    },
    "Start": {
      "boost": ["contact", "setCoil"],
      "scenes": ["startup"]
    },
    "Stop": {
      "boost": ["negatedContact", "resetCoil"],
      "scenes": ["shutdown", "interlock"]
    }
  },
  "blockPreferences": {
    "MC_Reset": {
      "boost": ["contactBefore", "negatedContactBefore"],
      "reason": "运动控制复位功能块前通常需要 Enable、Fault、Ready 等执行条件"
    },
    "TON": {
      "boost": ["contactBefore", "coilAfter"],
      "reason": "定时器常见模式是前置触发条件和后续输出使用"
    }
  }
}
```

该规则表只决定排序权重，不直接决定最终图结构。

## 推荐流程

建议整体流程如下：

```text
读取 diagram JSON
      ↓
定位当前 segment 和选中节点
      ↓
执行现有本地拓扑规则，生成合法 suggestions
      ↓
提取业务上下文
      ↓
根据业务规则为 suggestions 打分
      ↓
按分数排序，保留原有返回格式
      ↓
返回给前端渲染
```

## 返回结构

业务排序不改变当前 suggestion 主结构。

每条 suggestion 仍然保留：

- `id`
- `title`
- `startNodes`
- `endNodes`
- `position`
- `serialOrParallel`
- `text`
- `addNode`

可以考虑额外增加可选调试字段：

```json
{
  "businessScore": 12,
  "businessReasons": [
    "当前区段包含 Fault 变量",
    "选中功能块为 MC_Reset",
    "该建议是在功能块前补条件触点"
  ]
}
```

如果担心前端不需要这些字段，可以仅在 debug 模式返回。

## 典型场景

### 运动控制复位

当前选中 `MC_Reset` 功能块。

优先建议：

- 在 `MC_Reset` 前串联常开触点；
- 在 `MC_Reset` 前串联常闭触点；
- 与已有条件并联一个触点。

业务原因：

- `MC_Reset` 通常需要 `Enable`、`Execute`、`Fault`、`Ready` 等条件；
- 这些条件通常对应触点，而不是线圈。

### 报警复位

当前区段名称或变量包含 `Alarm` / `Reset`。

优先建议：

- 复位线圈；
- 常开复位触点；
- 常闭故障互锁触点。

### 启停控制

当前区段包含 `Start` / `Stop` / `Run`。

优先建议：

- `Start` 常开触点；
- `Stop` 常闭触点；
- 运行输出线圈；
- 自保持并联结构。

### 上下文不足

当前区段只有一个 `???` 触点。

处理方式：

- 不做业务猜测；
- 只返回拓扑合法建议；
- 新增节点仍然为 `???`。

## 非目标

第一版不做以下事情：

- 不直接自动生成真实变量名；
- 不强制替换用户已有变量；
- 不基于全项目做重型扫描；
- 不用大模型参与本地业务排序；
- 不改变现有 suggestion 基础格式。

## 后续扩展

后续可以逐步增加：

- 变量候选推荐；
- 设备模板推荐；
- 项目级共现统计；
- 用户自定义业务规则；
- 行业模板，例如水泵、阀门、气缸、报警、运动控制；
- 根据 ST 文件和图 JSON 联合分析业务语义。
